# Как устроен ai-search

Этот документ подробно описывает, что делает программа, из каких частей она состоит и что происходит на каждом этапе. Краткая инструкция по установке и командам находится в `README.md`.

---

## 1. Зачем это нужно

Когда вы работаете с ИИ-агентами (Claude Code, Codex, Gemini, Antigravity), каждая сессия начинается «с чистого листа». Агент не помнит, что вы делали вчера в другой сессии, какие решения приняли и какие проблемы уже решили.

ai-search решает эту задачу. Он:

1. **собирает** все прошлые переписки с агентами и файлы ваших проектов;
2. **понимает их смысл** с помощью локальной модели;
3. **находит нужное** по вопросу на обычном языке, даже если слова в вопросе не совпадают со словами в тексте;
4. **отдаёт найденное агенту**, и тот отвечает с учётом вашей прошлой работы.

Пример. Вы спрашиваете «как я проверял, выдержит ли сервер много пользователей». Обычный поиск по словам ничего не найдёт: в той сессии было написано «нагрузочное тестирование на Locust». ai-search найдёт её, потому что сравнивает смысл, а не буквы.

**Всё работает на вашем компьютере.** Индекс, модель и поиск находятся локально, и ничего не отправляется в интернет. Интернет нужен только один раз, при установке, чтобы скачать библиотеки и модель.

## 2. Общая схема

```
┌──────────────────────── ИСТОЧНИКИ ────────────────────────┐
│                                                           │
│  Переписки с агентами              Файлы проектов         │
│  ~/.claude/projects/*.jsonl        ~/Desktop/**           │
│  ~/.codex/sessions/*.jsonl         код, .md, .txt,        │
│  ~/.gemini/tmp/*/chats/*.json      PDF, DOCX              │
│  ~/.gemini/antigravity*/brain/*.md                        │
└───────────────┬───────────────────────────┬───────────────┘
                │                           │
                ▼                           ▼
┌───────────────────────────────────────────────────────────┐
│ ИНДЕКСАЦИЯ                                                │
│  1. Разбор:    вытащить текст, отбросить служебное         │
│  2. Нарезка:   куски по ~1500 символов                     │
│  3. Защита:    замаскировать ключи, токены, пароли         │
│  4. Дедуп:     одинаковые куски хранятся один раз          │
│  5. Векторы:   модель bge-m3 → 1024 числа на кусок         │
│  6. Запись:    в базу ~/.ai-search/index.db                │
└───────────────────────────┬───────────────────────────────┘
                            ▼
┌───────────────────────────────────────────────────────────┐
│ БАЗА  (один файл SQLite)                                  │
│  • векторы (sqlite-vec)  → поиск по смыслу                │
│  • полнотекст (FTS5)     → поиск по точным словам         │
│  • метаданные            → откуда кусок, дата, проект     │
└───────────────────────────┬───────────────────────────────┘
                            ▼
┌───────────────────────────────────────────────────────────┐
│ ПОИСК  (/search в агенте или ai-search search в терминале)│
│  вопрос → вектор → ближайшие по смыслу ─┐                 │
│  вопрос → слова  → совпадения по словам ┼→ объединение    │
│                                         ┘  → топ-10       │
└───────────────────────────┬───────────────────────────────┘
                            ▼
                    Агент читает найденное
                    и отвечает на ваш вопрос
```

Параллельно работает **фоновая служба**. Она следит за папками и сама обновляет индекс, когда что-то меняется (подробнее в разделе 6).

│   └── launchd.plist     шаблон автозапуска фоновой службы
└── ai_search/          код программы (Python)
    ├── config.py         чтение настроек
    ├── sources.py        поиск источников, разбор, нарезка, маскировка секретов

| Индекс | `~/.ai-search/index.db` | ~100–500 МБ |
| Журналы | `~/.ai-search/logs/` | мало |
| Автозапуск службы | `~/Library/LaunchAgents/com.local.ai-search.plist` | 1 КБ |
| Команды агентов | `~/.claude/skills/search/`, `~/.codex/skills/search/`, `~/.gemini/commands/search.toml` | 1–2 КБ |

## 4. Индексация: что происходит с каждым источником

### 4.1. Поиск источников

Программа обходит:

- **папки переписок**, перечисленные в `config.toml` в разделе `[chats]`. Отсутствующие папки просто пропускаются;
- **папки с файлами** из `file_roots` (по умолчанию `~/Desktop`).

**В папках с файлами пропускается:**

- служебные и сгенерированные папки: `node_modules`, `.git`, `venv`, `.venv`, `__pycache__`, `dist`, `build`, `.next`, `target`, `vendor`, `static`, `assets`, `public`, `logs`, `tmp` и другие;
- тесты и миграции: `tests`, `test`, `__tests__`, `fixtures`, `versions` (миграции alembic), `locales`;
- все скрытые папки (имя начинается с точки);
- папки с результатами рендеров (`*-output*`);
- всё, что вы перечислили в `exclude` в `config.toml`;
- сама папка `ai-search`.

**Какие файлы берутся:**

- код и текст: `.py .js .ts .tsx .jsx .vue .go .rs .java .kt .swift .c .cpp .cs .php .rb .sql .sh .md .txt .yaml .toml` и другие, размером до 1 МБ;
- данные и сборки (`.json .csv .html .js .css .xml .ipynb`): только до 100 КБ, потому что большие файлы таких типов обычно сгенерированы и бесполезны для поиска;
- документы `.pdf` и `.docx` размером до 30 МБ.

**Какие файлы не читаются никогда:** `.env`, `*.pem`, `*.key`, `*.p12`, `id_rsa*`, всё с `secret`, `credential` или `password` в имени, lock-файлы (`package-lock.json`, `poetry.lock` и т.п.), а также `*.min.js` и `*.map`.

### 4.2. Разбор: как из файла получается текст

| Источник | Что извлекается | Что отбрасывается |
|---|---|---|
| **Claude Code** (`.jsonl`) | ваши сообщения и ответы агента, название сессии, рабочая папка, время | вызовы инструментов и их вывод, «мысли» модели, системные вставки (`<system-reminder>` и т.п.), картинки |
| **Codex** (`.jsonl`) | сообщения пользователя и агента, рабочая папка | служебные инструкции (`AGENTS.md`, `environment_context`) |
| **Gemini CLI** (`.json`) | сообщения пользователя и модели | — |
| **Antigravity** (`brain/*.md`) | планы, задачи и отчёты агента | — (сами диалоги хранятся в закрытом формате и недоступны) |
| **Код и текст** | содержимое файла с номерами строк | бинарные файлы |
| **PDF** | текст по страницам | картинки |
| **DOCX** | текст абзацев | — |

**Переписки группируются по репликам:** ваш вопрос плюс все ответы агента до следующего вопроса составляют одну реплику. Так в одном куске оказываются и вопрос, и ответ на него.

### 4.3. Нарезка на куски

Модель понимает за раз ограниченный объём текста, около 512 токенов. Поэтому всё режется на **куски по ~1500 символов**.

- **Переписки:** длинная реплика делится на несколько кусков с перекрытием 200 символов, чтобы мысль не обрывалась на границе. Разрез по возможности делается по абзацу или концу предложения.
- **Код:** окнами до 60 строк с перекрытием 8 строк. Для каждого куска запоминается диапазон («строки 120–180»), чтобы агент мог открыть файл точно в этом месте.
- **PDF:** по страницам («стр. 3»).
- В каждый кусок файла добавляется строка `Файл: путь/к/файлу`, чтобы модель учитывала и имя файла.
- Из одного файла берётся не больше 300 кусков, чтобы одна огромная книга в PDF не забила индекс.

### 4.4. Маскировка секретов

**До записи в базу** текст проверяется на секреты, и найденное заменяется на `[СКРЫТО]`:

- приватные ключи (`-----BEGIN ... PRIVATE KEY-----`);
- ключи API: OpenAI/Anthropic (`sk-…`, `sk-ant-…`), GitHub (`ghp_…`, `github_pat_…`), AWS (`AKIA…`), Slack (`xox…`), Google (`AIza…`);
- JWT-токены (`eyJ…`);
- значения после `password=`, `secret:`, `token=`, `api_key=`, `PrivateKey =`, `PresharedKey =` и похожих.

Так секреты не попадают ни в индекс, ни в ответ агенту.

### 4.5. Удаление дублей

Одна и та же вставка часто встречается в нескольких сессиях, например одинаковый промпт, отправленный трижды. Каждый кусок получает «отпечаток» (SHA-1 хэш текста):

- текст и его вектор хранятся **один раз**;
- запоминаются все места, где он встречается;
- в выдаче такой кусок появляется один раз с пометкой «этот же текст ещё в N местах».

Это экономит и место, и время: повторный кусок не нужно снова прогонять через модель.

### 4.6. Векторы: модель bge-m3

Каждый уникальный кусок проходит через модель **BAAI/bge-m3**. Она превращает текст в **1024 числа**, своего рода «координаты смысла»:

```
«нагрузочное тестирование Locust»   → [0.12, -0.80, 0.33, …]
«load testing the API»              → [0.11, -0.78, 0.35, …]   близко
«выдержит ли сервер много юзеров»   → [0.14, -0.75, 0.30, …]   близко
«рецепт борща»                      → [-0.60, 0.20, -0.90, …]  далеко
```

Чем ближе смысл текстов, тем ближе их координаты, даже если тексты написаны на разных языках и разными словами.

**Почему bge-m3:**

- хорошо понимает **русский и английский вместе**, а переписки часто смешанные;
- бесплатная, работает **без интернета**;
- на Mac с Apple Silicon считает на видеоядре (MPS) в половинной точности: так быстрее и тратится меньше памяти.

Модель загружается в память, только когда нужна. Через 15 минут простоя она выгружается и освобождает ~1–2 ГБ оперативной памяти.

### 4.7. Запись в базу

База — это один файл `~/.ai-search/index.db` (SQLite). В нём:

| Таблица | Что хранит |
|---|---|
| `sources` | каждый проиндексированный файл: путь, тип, дата изменения, размер, ошибка (если не удалось прочитать) |
| `texts` | уникальные куски текста |
| `chunks` | где встречается каждый кусок: файл, агент, название сессии, проект, дата, место («строки 10–60», «реплика 5») |
| `vec` | векторы кусков (расширение sqlite-vec), для поиска по смыслу |
| `fts` | полнотекстовый индекс (FTS5, триграммы), для поиска по словам |

Запись идёт порциями по 64 куска. Каждая порция сразу сохраняется, поэтому поиск видит новые данные ещё до конца большой индексации.

### 4.8. Инкрементальность: индексируется только новое

Для каждого файла запоминаются **дата изменения и размер**. При следующем проходе:

- файл не менялся → пропускается;
- файл изменился → переразбирается, но в модель идут **только новые куски**, а для старых векторы берутся из базы (по отпечатку). Это важно для переписок: сессия растёт, и при каждом обновлении считаются векторы только для новых реплик;
- файл удалён → его куски убираются из индекса, а осиротевшие тексты и векторы удаляются.

**Порядок индексации:** сначала переписки, потом файлы **от самых свежих к старым**. Поэтому активные проекты становятся доступны для поиска первыми.

## 5. Поиск: что происходит при `/search`

### 5.1. Путь запроса

```
Вы:     /search как я настраивал traefik
           │
           ▼
Агент:  читает инструкцию команды и формулирует короткий запрос
           │
           ▼
        "~/Desktop/ai-search/ai-search" search "настройка traefik"
           │
           ▼
Программа: есть ли запущенная фоновая служба?
           ├─ да  → отправляет запрос ей (модель уже в памяти, быстро)
           └─ нет → загружает модель сама и ищет (медленнее, но работает)
           │
           ▼
        [проверка свежести, вариант Б] → [гибридный поиск] → текст результатов
           │
           ▼
Агент:  читает результаты, при необходимости открывает файлы целиком,
        ищет дополнительно через Spotlight и отвечает вам
```

### 5.2. Гибридный поиск

Запрос ищется **двумя способами одновременно**:

**1. По смыслу (векторы).** Вопрос превращается в вектор той же моделью bge-m3. В базе находятся 80 ближайших кусков по косинусной близости. Этот способ хорошо находит перефразировки, синонимы и тексты на другом языке.

**2. По словам (FTS5).** Из вопроса берутся слова длиннее 3 символов, у длинных русских слов отрезается окончание («нагрузочное» превращается в «нагрузочн»), чтобы находились другие формы слова. Используется триграммный индекс, который находит слово и внутри других слов. Отбираются 80 лучших совпадений по BM25. Этот способ точно находит имена: `safe-house-backend`, `inFlightReq`, номер ошибки.

**3. Объединение (RRF, Reciprocal Rank Fusion).** Каждый кусок получает очки `1 / (60 + место в списке)` за каждый список, где он встретился. Кусок, который нашёлся обоими способами, поднимается выше. Так соединяются сильные стороны двух методов: смысл и точность.

**4. Выдача.** По умолчанию 10 лучших результатов. Для каждого показывается:

- тип (переписка или файл), агент, дата;
- название сессии и рабочая папка или путь к файлу и строки;
- «близость» по смыслу (от 0 до 1, чем больше, тем ближе);
- фрагмент текста до 600 символов вокруг найденного места.

Пример:
```
[1] переписка · claude · 2026-10-29 05:31 · реплика 33 · близость 0.657
    Сессия: Locust нагрузочное тестирование Safe House | папка: ~/Desktop/locust
    Файл сессии: ~/.claude/projects/…/f668c8e0-….jsonl
    …1000 пользователей с паузой 1–5 с — это около 300 запросов в секунду…
```

### 5.3. Параметры поиска

```bash
ai-search search "вопрос"                 # всё
ai-search search "вопрос" --kind chats    # только переписки
ai-search search "вопрос" --kind files    # только файлы
ai-search search "вопрос" -n 5            # 5 результатов (меньше токенов)
ai-search search "вопрос" --json          # машиночитаемый вывод
```

## 6. Как индекс остаётся свежим

### Вариант А. Фоновая служба следит за папками

Служба запускается автоматически при входе в систему через `launchd`, стандартный механизм macOS, и перезапускается, если упадёт.

```
 Вы сохранили / перетащили / удалили файл
            │
            ▼  macOS (FSEvents) мгновенно сообщает службе
 [1] Событие записывается в очередь
            │
            ▼
 [2] Ожидание тишины
       • 5 секунд для файлов
       • 20 секунд для переписок (сессия активно пишется)
       Если файл продолжает меняться, таймер сбрасывается.
       Так файл не индексируется 10 раз во время сохранения.
            │
            ▼
 [3] Проверка: подходит ли файл (тип, размер, не секрет, не в исключениях)
            │
            ▼
 [4] Индексация только этого файла (или удаление из индекса)
            │
            ▼
 Через ~10–30 секунд файл находится через /search
```

**За чем следит служба:** `~/Desktop`, `~/.claude/projects`, `~/.codex/sessions` и `~/.gemini`, то есть за всеми папками из настроек, которые существуют.

**Свежие изменения идут вне очереди.** Даже если служба в этот момент делает большую первую индексацию на час, новые файлы обрабатываются между порциями, а не ждут её окончания.

**Если переместили или удалили целую папку**, служба делает полную сверку индекса с диском.

**При запуске** (например, после перезагрузки Mac) служба сначала сверяет индекс с диском и догоняет всё, что изменилось, пока она была выключена.

### Вариант Б. Проверка перед каждым поиском

Это страховка. Перед поиском программа быстро сравнивает даты изменения файлов с базой:

- новых изменений нет → сразу ищет;
- есть до 50 изменений → сначала доиндексирует их, потом ищет;
- больше 50 → ищет сразу и предупреждает, что часть изменений ещё индексируется в фоне;
- индекс в этот момент обновляет служба → ищет сразу и тоже предупреждает.

Этот вариант выручает, если служба была выключена, Mac спал или событие от системы потерялось.

### Защита от конфликтов

Служба и ручной запуск `ai-search index` могут попытаться обновлять индекс одновременно. Чтобы они не мешали друг другу, используется файловая блокировка `~/.ai-search/index.lock`: индекс в каждый момент обновляет только один процесс. Читать базу при этом можно параллельно (режим WAL в SQLite).

## 7. Фоновая служба изнутри

| Параметр | Значение |
|---|---|
| Запуск | `launchd`, при входе в систему, автоперезапуск при падении |
| Приоритет | фоновый: пониженный приоритет CPU (`Nice 10`) и диска (`LowPriorityIO`) |
| Сеть | локальный сервер `127.0.0.1:47400`, доступен **только с этого компьютера** |
| Память | ~200 МБ без модели; ~1.5–2.5 ГБ, пока модель загружена |
| Выгрузка модели | через 15 минут без работы |
| CPU в простое | ~0%: служба спит, пока macOS не сообщит об изменениях |
| Журналы | `~/.ai-search/logs/daemon.log` |

Локальный сервер нужен для скорости: модель уже загружена в службе, поэтому поиск через неё не тратит время на загрузку модели при каждом запросе.

---

## 8. Подключение к агентам

`install.sh` создаёт команду поиска для каждого установленного агента:

| Агент | Файл | Вызов |
|---|---|---|
| Claude Code | `~/.claude/skills/search/SKILL.md` | `/search <вопрос>` |
| Codex | `~/.codex/skills/search/SKILL.md` | `$search <вопрос>` |
| Gemini CLI | `~/.gemini/commands/search.toml` | `/search <вопрос>` |
| Любой другой | — | попросите агента запустить `~/Desktop/ai-search/ai-search search "<вопрос>"` |

Все команды содержат одну и ту же инструкцию (`templates/instructions.md`). Агент должен:

1. запустить поиск по индексу: переписки и файлы проектов;
2. при необходимости дочитать важные находки (открыть файл на нужных строках);
3. если вопрос о файлах вне индекса, поискать через Spotlight (`mdfind`) по всему домашнему каталогу;
4. ответить, начав с блока «**Что нашёл:**» со ссылками на сессии и файлы.

Если до установки у агента уже была своя команда `search`, она сохраняется в `~/.ai-search/backup/`, а `uninstall.sh` возвращает её на место.

## 9. Расход ресурсов и токенов

**Индексация токенов не тратит.** Векторы считает локальная модель на вашем Mac.

**Скорость индексации:** ~14 кусков в секунду на M2 Pro.

- переписки (~2 600 кусков): 2–3 минуты;
- проекты на Desktop (~10 000 файлов): до часа–полутора в фоне при первом запуске; потом только изменения, за секунды.

**Один вызов `/search` стоит агенту ~8–20 тысяч токенов:**

| Что попадает агенту | Токенов |
|---|---|
| инструкция команды | ~0.5k |
| 10 результатов по ~600 символов | ~3–4k |
| дочитывание 1–2 находок | ~2–6k |
| поиск по Spotlight и чтение файлов (если нужно) | ~2–10k |

Обычные вопросы без `/search` не тратят ничего дополнительно.

## 10. Конфиденциальность

- Модель, индекс и поиск работают **локально**, на вашем Mac.
- Фоновая служба принимает запросы только с этого компьютера (`127.0.0.1`).
- Секреты маскируются **до** записи в индекс, а файлы с ключами не читаются вообще.
- Наружу уходит только то, что агент (Claude, Codex, Gemini) сам получает в ответ на `/search`, то есть найденные фрагменты. Они идут к провайдеру этого агента, как и любой текст в обычном диалоге.

**Ограничение:** маскировка работает по шаблонам и не может поймать всё. Не храните пароли в обычных заметках и коде.

## 11. Настройки (`config.toml`)

```toml
file_roots = ["~/Desktop"]          # какие папки индексировать
exclude = ["work/archive"]          # что пропустить (пути относительно папки, можно *)

[chats]                             # где лежат переписки агентов
claude = ["~/.claude/projects/**/*.jsonl"]
...

[index]
model = "BAAI/bge-m3"
max_text_mb = 1                     # максимальный размер текстового файла
max_doc_mb = 30                     # максимальный размер PDF/DOCX
debounce_files_sec = 5              # ожидание тишины для файлов
debounce_chats_sec = 20             # ожидание тишины для переписок
model_idle_unload_min = 15          # когда выгружать модель
precheck_max_changes = 50           # предел доиндексации перед поиском

[server]
port = 47400

[search]
limit = 10                          # результатов по умолчанию
snippet_chars = 600                 # длина фрагмента
```

После изменений выполните `ai-search restart`. Если вы убрали папки из индекса, выполните ещё `ai-search index`, чтобы удалить их из базы.

## 12. Команды

| Команда | Что делает |
|---|---|
| `ai-search search "вопрос"` | поиск |
| `ai-search status` | что проиндексировано, работает ли служба, прогресс |
| `ai-search index` | вручную проверить и проиндексировать изменения |
| `ai-search index --only chats` | только переписки |
| `ai-search index --full` | удалить индекс и построить заново |
| `ai-search start` / `stop` / `restart` | управление фоновой службой |
| `ai-search logs` | журнал службы в реальном времени |
| `ai-search download-model` | скачать или проверить модель |
| `./install.sh` | установить или обновить (повторный запуск безопасен) |
| `./uninstall.sh` | удалить службу, команды, а также, по желанию, индекс и модель |

### Как понять, что индексация закончилась

```bash
ai-search status
```

Смотрите строку «Фоновая служба»:

- `индексирует: 880/8901 источников` — ещё идёт;
- `ждёт изменений` — всё готово, служба только следит за новыми файлами.

## 13. Ограничения

- **Только macOS:** используются `launchd` и FSEvents. Лучше всего работает на Apple Silicon (M1 и новее).
- **Antigravity:** сами диалоги хранятся в закрытом формате, поэтому индексируются только планы и отчёты (`brain/*.md`).
- **Картинки, видео, аудио и архивы** не индексируются, ищется только текст.
- **Сканы PDF без текстового слоя** не читаются: распознавания текста (OCR) нет.
- **Первая индексация большого Desktop** идёт долго, зато в фоне, и поиск работает сразу.
- **Маскировка секретов** работает по шаблонам и не гарантирует 100% результата.

## 14. Если что-то не работает

| Проблема | Что делать |
|---|---|
| `/search` нет в агенте | перезапустите агента (Claude Code / Codex / Gemini) |
| «ai-search не установлен» | `./install.sh` |
| служба не запущена | `ai-search start`, потом `ai-search status` |
| новые файлы на Desktop не находятся | Системные настройки → Конфиденциальность и безопасность → Доступ к файлам и папкам → разрешите python доступ к «Рабочему столу» |
| первый поиск идёт ~20 секунд | модель загружается после простоя, следующие поиски быстрее |
| поиск находит мусор из старых папок | добавьте их в `exclude`, затем `ai-search restart` и `ai-search index` |
| нужно начать с нуля | `ai-search index --full` |
| ошибки | `ai-search logs` или `~/.ai-search/logs/daemon.err.log` |
